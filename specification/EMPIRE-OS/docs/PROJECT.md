# PROJECT RULES

## Empire OS Engineering Standards

Version: 1.0

Status: Official

---

# Purpose

This document defines the engineering standards for Empire OS.

Every AI, developer, contributor, and future team member must follow these rules.

These rules ensure consistency, maintainability, scalability, and long-term project quality.

---

# Rule 1 — Empire Bible Comes First

The Empire Bible has the highest authority.

No feature, architecture, or code may violate the Empire Bible.

---

# Rule 2 — Founder Has Final Authority

The Founder has the final decision on every major change.

Suggestions are encouraged.

Unauthorized changes are prohibited.

---

# Rule 3 — Documentation Before Development

Before building a new system:

- Understand the requirement.
- Check existing documentation.
- Avoid duplicate work.

---

# Rule 4 — Build Small

Never build huge systems in one step.

Break everything into small working modules.

---

# Rule 5 — One Working Feature Every Week

Empire OS must gain at least one fully working feature every week.

Working software is the primary measure of progress.

---

# Rule 6 — Reuse Before Rebuild

Always reuse existing systems before creating new ones.

Avoid unnecessary duplication.

---

# Rule 7 — Modular Architecture

Every system must remain independent.

Examples:

Brain

Memory

Workers

Automation

Business

Security

Each module should be replaceable without breaking the entire project.

---

# Rule 8 — Clear Naming

Use meaningful names.

Avoid abbreviations.

Good Example:

BusinessMemory

Bad Example:

BM

---

# Rule 9 — Clean Folder Structure

Every file belongs in the correct folder.

Never create random folders.

---

# Rule 10 — Security First

Never expose:

Passwords

API Keys

Tokens

Personal Data

Secrets

Use environment variables whenever possible.

---

# Rule 11 — AI Independence

Empire OS must work with any future AI platform.

Never design the system around one AI provider.

---

# Rule 12 — Every Decision Must Be Logged

Any architectural or strategic decision must be recorded inside:

DECISIONS.md

---

# Rule 13 — Every Update Must Be Logged

Every important change must be recorded inside:

CHANGELOG.md

---

# Rule 14 — Simplicity Wins

Prefer the simplest solution that solves the problem.

Avoid unnecessary complexity.

---

# Rule 15 — Solve Real Problems

Every feature must answer at least one question:

Does this save time?

Does this solve a problem?

Does this create business value?

Does this improve execution?

If the answer is "No", the feature should not be built.

---

# Rule 16 — Long-Term Thinking

Never optimize only for today.

Design systems that remain useful for years.

---

# Rule 17 — Continuous Improvement

Empire OS is never finished.

Every version should become:

Smarter

Faster

Safer

More useful

---

# Rule 18 — Protect Project Quality

Quality is more important than speed.

Build once.

Improve forever.

---

# Final Principle

Empire OS exists to extend the Founder's capabilities.

Every line of code, every document, every AI Worker, and every automation must increase the Founder's ability to build, manage, and scale businesses.
